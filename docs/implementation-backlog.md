# AI 开发任务拆解 v1

日期：2026-09-19。目标：在 `ai_life_apply/` 根目录持续实现 [technical-design.md](./technical-design.md)，每次交付可运行功能切片。

本文件是任务计划，不表示任务已执行。M0 文档在本轮补齐；M1–M8 的实现状态由代码和验收证据决定。现有演示代码保留可复用部分，不重新建一套子项目。

## 1. 任务执行契约

每个任务遵循：读适用 AGENTS/当前 Git 状态 → 读本任务契约与依赖 → 必要时补迁移/API → 编码完整切片 → 执行有意义的本地验证 → 记录证据和限制 → 提交小范围变更。

变更清单必须含：页面/接口、数据表或 schema、任务/产物状态、验收 ID、运行方式、外部前提、实际检查结果。一个 AI 编码代理可顺序完成；不要求多 Agent 产品框架，也不默认并行代理开发。

不得把 `demo-user`、固定旁白文本、图片数量、标题卡 MP4 的成功，计入正式登录、真实语音、真实生图或完整视频验收。

## 3. 首批具体改动顺序

1. 收敛 `backend/app/main.py` 为装配入口，先分离配置、错误和数据库访问；保持现有演示可运行，随后切正式认证。
2. 前端改同源 `/api/v1`，Nginx/Vite 代理配置一致；生成 types，替换混用 camelCase/snake_case 的手工契约。
3. 建最小 users/workspaces/sessions/projects/source_documents/script_versions 和 Alembic；两个隔离测试用户验证。
4. 建 assets、版本快照、runs/nodes/attempts/outbox、额度/报价；没有这些不开放真实批量生图。
5. 用自建图片、音轨夹具完成真正多镜头小片和字幕；输出不能继续只是无声片头卡。
6. 文本/图像/语音渠道各自完成一个真实小样，记录能力缺口后再做批量与完整 UI。
