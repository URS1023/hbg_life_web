# 验收计划与发布门槛 v1

日期：2026-09-19。本文定义未来验收，不是测试通过报告。本轮只检查代码与文档，未连接数据库、启动应用或调用模型。

## 1. 验收层级和证据

| 层级 | 范围 | 能证明什么 | 不能代替什么 |
| --- | --- | --- | --- |
| L0 静态/契约 | Web 类型构建、Python 检查、迁移结构、schema、文档引用 | 工程与契约基本一致 | 不能证明登录、并发或生成正确 |
| L1 本机业务 | 账户、归属、版本、额度、状态机 | 业务约束及异常处理正确 | SQLite 不能替代 PostgreSQL 事务/锁验证 |
| L2 本机集成 | PostgreSQL/Redis、Worker、私有存储、真实 FFmpeg | 持久任务和真实媒体闭环 | mock 图片/声音不能证明供应商集成 |
| L3 浏览器 | 实际八步操作、刷新恢复、试听、选图、下载 | 用户能完成任务，界面反映后台状态 | 不能用仅 API 成功替代 |
| L4 真实渠道 | 文本/图片/TTS 小样和实际短片 | 指定渠道/模型/配置可用 | 一个渠道成功不能推出所有兼容渠道均可用 |
| L5 本机部署演练 | 迁移、启动、重启、备份恢复、版本回退 | 部署包可复现 | 不代表已在公网部署或已验证生产容量 |

每条记录：case_id、commit、环境、实际数据库身份、mode(mock/real)、输入快照、操作、预期/实际、请求与查询数量、耗时、产物/日志位置、结果(pass/fail/blocked/not_run)。截图不能替代事件与文件证据；敏感内容保存在 Git 忽略的验收目录，只提交脱敏摘要。

## 2. 本地数据库硬边界

1. 任何通过脚本、API、浏览器间接触发的数据测试前，核实实际 host、port、database、服务进程/容器归属、Docker context 和端口链路；仅 `localhost` 字样不足以证明本地。
2. 使用新建的本机隔离验收库，例如 `ai_life_apply_test`，该名称仅为建议，不连接已有同名库直到完成核实。不修改其他项目或在用工作流的数据源绑定。
3. 所有行均使用自建测试账户/脚本；不读写现有业务数据、不调数据库全局配置、不擅自建业务库索引。
4. 单连接先跑 schema 和单条业务查询；性能问题先看 EXPLAIN，默认不加 ANALYZE。小样预算建议：1 个查询类型、并发 1、最多 3 轮、每轮 1 次、statement_timeout 3 秒、整轮 30 秒，记录实际数量。此为候选起点，执行前再确认环境。
5. 功能竞态测试先顺序跑通，再在临时库用 2 个请求验证一次冲突，设置每用例总时间/请求数上限；不是持续压测，不扩成循环。
6. 超时、断连、资源异常即停止后续测试，检查在途查询/进程是否结束；不自动重试、加超时、恢复循环、切换其他数据源。异常修复后按用户明确授权继续。

## 3. 功能和异常验收矩阵

以下各项初始状态均为未执行；历史演示测试只能作为局部参考。

| ID | 场景 | 明确通过条件 |
| --- | --- | --- |
| AUTH-01 | 邀请注册、登录、退出、禁用 | 邀请只能用一次；密码摘要存储；退出/禁用后旧会话失效；生产无 demo 回退 |
| AUTH-02 | 两用户 A/B 的资源隔离 | B 读取/修改/删除 A 的 project/shot/asset/run/export、下载和 SSE 均不可得；批量接口同样检查 |
| AUTH-03 | 嵌套 ID/上传认领 | 把 A 的 asset/shot/key 放入 B 的合法路径或上传完成请求也失败，无副作用 |
| AUTH-04 | Cookie 与 CSRF | 无 token/错误 Origin 的写请求拒绝；登录后轮换会话；管理员接口不被普通会话调用 |
| PROJ-01 | 关键词路径 | 保存简报，生成真实结构化规划和可编辑正文，刷新后数据仍在 |
| PROJ-02 | 已有脚本保留 | 原文逐字可回读；未经选择不改剧情；编辑稿和差异独立保存 |
| VER-01 | 两个页面并发编辑 | 旧 ETag 返回 412，本地输入保留；没有静默丢失更新 |
| VER-02 | 旧生成晚到 | 修改角色/脚本后旧任务结果仅成历史候选；最新选用不变 |
| CHAR-01 | 角色和场景参考 | 至少 1 个主角、1 个场景生成可打开参考图；镜头请求记录并实际传入所选图 |
| VOICE-01 | 试听到正式旁白 | 试听/正式分别计量；正式可播放、有实际时长及生成标识，不能只有数量元数据 |
| VOICE-02 | 字幕时间来源 | provider/alignment 来源明确，全文覆盖、时间有序；数字和重复语句不会错配 |
| SHOT-01 | 分镜编辑与提示词 | 可新增/拆分/合并；提示词绑定具体人物场景版本；镜头边界由真实音频校准 |
| IMG-01 | 部分失败 | 自建 6 镜头夹具中第 3 镜头明确失败，其余成功并保留；只重做第 3 镜头，调用计数吻合 |
| IMG-02 | 选图和上传替换 | 候选历史仍在；选新图只使相关片段/导出失效，不重新生成语音 |
| AUDIO-01 | BGM/SFX 混音 | 可选择/上传、改变音量与淡入淡出；无 BGM 也能导出；旁白不被截断 |
| TASK-01 | 相同请求重复提交 | 同幂等键顺序/一次并发提交返回同 run；预留和 provider 提交数量不重复 |
| TASK-02 | 重复 Celery 投递 | 同 node 两次投递只有一个有效租约；失效 token 不能写成功 |
| TASK-03 | Worker 中断恢复 | 只中断隔离测试 Worker；已成功节点不重做，剩余节点恢复；外部在途结果先核对 |
| TASK-04 | broker 投递窗口 | mock 注入发布后未写标记、消息丢失两种情况；outbox/扫描最终恢复，无重复费用 |
| TASK-05 | 供应商超时未知 | mock 已受理但响应丢失，进入 reconciling；未查询清楚前不再次提交；预留可解释 |
| TASK-06 | 取消竞态 | queued 不调用供应商；running 停止后续节点；FFmpeg 进程组结束；在途请求有最终核对 |
| TASK-07 | 重复与乱序回调 | 无重复素材注册/结算；旧 pending 不覆盖 succeeded；错误签名拒绝 |
| COST-01 | 额度预留和释放 | 100→预留30→消费18→释放12 后可用82/预留0/已用18，ledger 可重建余额 |
| COST-02 | 额度不足/并发 | 两笔同时预留不能超支；实际消费超过预算不自动变负数；管理员调整留原因 |
| COST-03 | 供应商成本分离 | 失败也可记录供应商费用；用户免扣策略不会抹去平台成本 |
| FILE-01 | 文件隔离与校验 | 超限、扩展名伪装、不可解码文件拒绝；不允许任意 URL/路径/符号链接跳出 scratch |
| FILE-02 | 下载权限和播放 | MP4 Range 返回正确数据；未登录/跨空间无权；过期链接可重新签发而无需重新生成 |
| EVT-01 | 页面刷新/断线 | 服务端继续；重连补齐事件且去重；过期 cursor 重取快照；新项目页面不被旧响应覆盖 |
| EXPORT-01 | 横竖屏完整导出 | 16:9 与 9:16 各一个可播放、有旁白、正确镜头和字幕的 MP4；非标题卡替身 |
| EXPORT-02 | 同项目并行导出 | 两个 export 的目录/文件分开，历史下载不被覆盖 |
| QA-01 | 检测工具失败 | 模拟 FFprobe/滤镜执行失败，报告 error 且阻止 ready；空 blackdetect 不自动掩盖失败 |
| QA-02 | 预览与成片一致 | 同 timeline/manifest 摘要；镜头顺序、裁剪、字幕、音效位置一致，仅分辨率/码率可不同 |
| OPS-01 | 同源部署 | 浏览器经网站域名访问 API，静态产物不硬编码 localhost；SSE 代理及时传输 |
| OPS-02 | 备份/恢复 | 本机临时库和媒体恢复后能打开同一项目及历史 MP4；孤立引用被识别 |
| OPS-03 | 模式与配置 | real 缺模型配置时报不可用；mock 在页面/任务/验收报告有标记；凭据不进入前端与日志 |

## 4. 媒体客观门禁与人工质量

| 检查 | 初始通过标准 | 处理 |
| --- | --- | --- |
| 完整解码 | FFprobe 和完整 FFmpeg 解码均成功；至少一视频和一音频流 | 失败阻断 |
| 规格 | manifest 指定尺寸、30fps、H.264/AAC、yuv420p，帧数与清单一致（容许编码器一帧边界差并记录） | 超界阻断 |
| 时长 | 预期 timeline 与成片差≤100ms；旁白未截尾 | 超界阻断；AAC padding 单独解释 |
| 字幕结构 | 0≤start<end≤timeline；文本覆盖原朗读稿；无非预期重叠；横竖屏安全区内 | 结构错误阻断 |
| 抽样音字同步 | 开头/转折/结尾至少 10 个检查点，目标≤200ms | 初始验收目标，需真实音频人工复核；失败回对齐 |
| 黑场/静音 | 报告位置、持续时间及与模板意图的关系 | 缺图/缺音阻断；创作性停顿为可解释警告 |
| 音频 | 默认建议综合响度 -18 至 -14 LUFS、True Peak≤-1dBTP，无削波，旁白清晰 | 项目交付目标，不宣称平台统一规定；偏离需调整或记录模板例外 |
| 人物场景 | 主角身份在样张及至少 5 个关键镜头可辨；无明显肢体/道具/时代冲突 | 人工复核；自动相似度不能替代 |
| 参考图与字体 | 引用图真实传入、中文字可读、不裁切关键内容 | 不满足不能以格式通过替代质量通过 |

这些数值是首版建议验收阈值，要通过真实样片校准；并非已实测指标或第三方平台承诺。

## 5. 真实渠道最小验收包

在指定真实渠道、调用范围和预算落实后：先各验证一次文本、单张图、短语音；通过后制作自建 30–60 秒、约 6–10 镜头短片，避免直接全量长片。关键词和保留脚本两条路径都要有证据；横竖屏均导出，参考图/裁剪不适配时记录补图成本。

记录供应商/模型/配置版本、请求 ID、实际计量、首次产物耗时、重做数量和成片 QA。真实调用失败后不得伪造请求 ID 或换 mock 标成功；缺渠道标 blocked，其他独立开发继续。

## 6. 自动化和发布门槛

CI 按顺序覆盖锁文件安装、Web 类型和构建、后端业务测试、本机隔离数据库的迁移/权限/额度契约、FFmpeg 小夹具、浏览器关键路径。CI 的 PostgreSQL/Redis 必须在执行器本机服务容器内；如迁到远程执行环境，其数据库必须仍是该执行器本机服务，不得用网络地址代替本地服务归属核实。

若当前任务仅获准在用户当前机器测试，则远程 CI 数据库执行需额外明确授权；准备 CI 配置并不代表可以替用户启动远程数据库测试。本轮文档提交不修改或新增数据库 CI 执行任务。

P0 放行须同时满足：AUTH/VER/TASK/COST/FILE 的阻断项全通过；两条输入路径均真实生成；所有八步都有实际产物与失败恢复；横竖屏成片通过 QA；本机部署/恢复演练有证据；管理员可看到额度和失败原因；不留假成功/占位主流程。

未完成项必须以具体 ID 列出，不用“基本完成”“构建通过”代替发布结论。真实外部部署是另一个环境验收，不由本地通过自动推断。
